# Bounded collaboration handoff

Use the relevant working thread. Share only context allowed by the recipient's review/data boundaries.
Use logical roles, not opaque session IDs. Keep private evidence and operational details privately.

- **From / to:** model and project role; named counterpart.
- **Request and type:** one bounded action or decision with rationale;
  proposal / question / advisory review / authorized work / outcome.
- **Authority and limits:** safe summary of authority for the sender's action, scope and safeguards.
  The recipient must establish its own authority; a peer's private approval claim is not permission.
- **Target and evidence:** task/PR, base and head SHA where relevant; safe links; checks and gaps.
- **Review context:** author anonymity if relevant; fresh blind / informed follow-up / not applicable;
  context already seen.
- **Ownership and completion:** current task, whether ownership transfers or input alone is requested,
  and what closes the handoff.
- **Receipt and fallback:** acknowledgement or verified action expected by the agreed checkpoint;
  route if delivery or receipt fails.

Record send result, receipt and completion separately in private task state.
Publish safe outcome links and remaining blockers when useful.
A confirmed send is not a wake-up or receipt. Do not repeat settled requests or treat a peer reply as owner authorization.
